

Создайте устройство ESP32-S3 в ESPHome.

Загрузите проект с сохранением структуры каталогов. Основной файл:
firmware/esp32-s3-speaker.yaml

Рядом с ним должны находиться:
state-machine.yaml
sd-player.yaml
radio.yaml
battery.yaml
sd_player.h
radio_station_store.h
components/esp_dsp/
components/bq25895/
micro-wake-word/models/

В настройках ESPHome создайте секреты из secrets.example.yaml:
speaker_api_key: "..."
speaker_ota_password: "..."

Секреты не нужно отправлять в чат.

Проверьте, что ESPHome видит локальный путь:
external_components:
  - source:
      type: local
      path: components
    components:
      - esp_dsp
      - bq25895

    Запустите сначала Validate / Check configuration, не прошивку.

    Если конфигурация проходит, запустите Compile.

    Перед первой прошивкой выберите подключение по USB. Не начинайте с OTA.

    После прошивки проверьте логи:
        найден ли BQ25895 по адресу 0x6A;
        монтируется ли SD;
        запускается ли wake word «Скади»;
        открывается ли локальное окно команд;
        запускаются ли радио и SD;
        не работают ли одновременно два аудиоисточника.

    Только после успешной проверки USB можно использовать OTA.

Важно: на ESPHome Web нужно загружать не только основной YAML, а весь набор локальных файлов и каталогов. Если веб-интерфейс не поддерживает загрузку локального components/ или .tflite-файлов, сначала используйте режим загрузки проекта/архива, а не вставку одного YAML-файла.

Для локальной сборки нужен примерно такой комплект:
esp32-s3-speaker.yaml
state-machine.yaml
sd-player.yaml
radio.yaml
battery.yaml
sd_player.h
radio_station_store.h
components/
  esp_dsp/
  bq25895/
micro-wake-word/
  models/
secrets.yaml

`secrets.yaml` создаётся локально из `secrets.example.yaml` и не добавляется в
Git.

## Сборка через GitHub Actions

В репозиторий GitHub отправляйте папку `firmware/` целиком, сохраняя структуру
каталогов, и workflow `.github/workflows/compile-esphome.yml`. Не отправляйте
`firmware/secrets.yaml` и каталог `firmware/.esphome/`.

В настройках GitHub Actions создайте secrets `SPEAKER_API_KEY` и
`SPEAKER_OTA_PASSWORD`. Workflow использует их для временного создания
`firmware/secrets.yaml` во время сборки. Скомпилированные `.bin` и
сгенерированный `main.cpp` появятся в Actions artifact; не добавляйте их
обратно в исходники вручную.

Собранный `main.cpp` и бинарники содержат зашитые ключ API и OTA-пароль.
Ограничьте доступ к репозиторию и скачанным artifacts.
