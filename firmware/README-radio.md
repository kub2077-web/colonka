# Автономное интернет-радио

`radio.yaml` — отдельный ESPHome-пакет для локального интернет-радио. Он
не требует Home Assistant для запуска станции: ESP32 сам подключается к
указанному HTTP/HTTPS-потоку и воспроизводит его через I2S-динамик.

Список станций не хранится на SD-карте и не требует отдельного сервера. В
прошивке предусмотрено шесть фиксированных слотов. Каждый слот состоит из
трёх отдельных entities: названия, URL потока и переключателя включения.
Значения сохраняются во flash через ESPHome Preferences и редактируются через
встроенный веб-сервер.

Пакет не изменяет базовую конфигурацию и не добавляет радио в основной YAML
автоматически.

## Подключение

В `esp32-s3-speaker.yaml` добавляется только пакет:

```yaml
packages:
  radio: !include radio.yaml
```

Если пакет состояния ещё подключается в том же разделе, итоговый блок должен
выглядеть так:

```yaml
packages:
  state_machine: !include state-machine.yaml
  radio: !include radio.yaml
```

Порядок пакетов важен только для читаемости: `radio.yaml` использует ID,
объявленные базовой конфигурацией и `state-machine.yaml`.

## Обязательные входы

Пакет ожидает следующие сущности.

### Из базовой конфигурации

```yaml
speaker:
  - platform: i2s_audio
    id: voice_speaker
```

`voice_speaker` — физический аудиовыход MAX98357A. Радио добавляет mixer-inputs
и направляет их в этот динамик.

### Из `state-machine.yaml`

Скрипты:

```text
sm_set_radio_source
sm_playback_started
sm_playback_failed
sm_route_stop
```

Глобальные переменные:

```text
sm_playback_source
sm_next_requested
sm_previous_requested
sm_stop_requested
```

Пакет не создаёт и не переопределяет эти сущности. Если подключить `radio.yaml`
без `state-machine.yaml`, конфигурация не скомпилируется — это намеренный
контракт пакета.

## Настройка станций

При первой прошивке шесть станций уже предзагружены в `radio.yaml` через
`initial_value`. Вводить их вручную через веб-панель не требуется. После
изменения через веб-панель новые значения сохраняются во flash ESPHome и
восстанавливаются после перезагрузки.

Для каждого из шести слотов доступны:

```text
Радиостанция N — название
Радиостанция N — URL
Радиостанция N — включена
```

Название ограничено 64 символами, URL — 255 символами. При изменении любого
поля список активных станций пересчитывается автоматически. Выключенный слот
исключается из переключения, но его название и URL сохраняются.

Для первой версии нужны прямые MP3-потоки по HTTP/HTTPS. Страница станции,
ссылка на плейлист или `m3u` без прямого аудиопотока не являются заменой URL
потока.

`firmware/data/stations.json` остаётся проектным seed-документом и удобным
списком исходных станций. Рабочими настройками после прошивки являются
отдельные entities слотов.

## Сущности и точки управления

Пакет создаёт:

| ID                           | Назначение                                                             |
| ---------------------------- | ---------------------------------------------------------------------- |
| `radio_media_player`         | общий media player для локального радио и управления из Home Assistant |
| `radio_current_station_name` | текстовое имя выбранной станции                                        |
| `radio_status`               | `Остановлено`, `Подключение`, `Воспроизводится` или `Ошибка потока`    |
| `radio_start_button`         | запуск выбранной станции                                               |
| `radio_stop_button`          | остановка                                                              |
| `radio_next_button`          | следующая станция                                                      |
| `radio_previous_button`      | предыдущая станция                                                     |

Скрипты для других модулей:

```text
radio_start
radio_request_stop
radio_next
radio_previous
radio_apply_stop
```

## Точки входа автомата состояний

Когда радио запускается, пакет вызывает:

```text
sm_set_radio_source
```

Когда media player подтверждает начало воспроизведения:

```text
sm_playback_started
```

Когда поток неожиданно заканчивается или становится недоступным:

```text
sm_playback_failed
```

`sm_route_next`, `sm_route_previous` и `sm_route_stop` из автомата состояний
выставляют request-флаги. Радио проверяет их каждые 250 мс и очищает только
те флаги, которые относятся к источнику `RADIO` (`sm_playback_source == 1`).
Это оставляет те же точки входа свободными для будущего `sd-player.yaml`.

## Управление из Home Assistant

`radio_media_player` можно использовать как обычный media player Home
Assistant. Локальные кнопки запускают заранее заданные станции, а Home
Assistant может отправить этому же player другой `media_url`, например поток
с сервера Home Assistant или Яндекс Музыку.

В каждый момент времени предполагается один активный источник. При запуске
радио предыдущий поток останавливается. Правило переключения между радио,
SD и `HA_MEDIA` должно оставаться в общем автомате состояний.

## Ограничения первой версии

- предусмотрено шесть слотов станций;
- названия ограничены 64 символами, URL — 255 символами;
- прямые MP3-потоки;
- без HLS/AAC-специфики;
- без отдельного аудиомикширования голоса и музыки;
- радио, SD и голосовой ответ не должны одновременно писать в один источник
  звука без отдельной политики ducking/mixing.

## Зачем отдельный пакет

`radio.yaml` содержит только радио-логику и её контракт. Базовые GPIO,
Wi-Fi, I2S, микрофон, голосовой ассистент и автомат состояний остаются
источниками истины в своих файлах. Будущий SD-плеер сможет использовать тот
же физический `voice_speaker` и те же request-флаги, не копируя код радио.
